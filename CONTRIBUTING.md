# Contributing

Thank you for helping maintain **Serene Klenam Mensah's portfolio**. All portfolio credit belongs to Serene; contributors assist with development and maintenance.

## Scope and workflow

1. For substantial changes, open an issue describing the problem and proposed scope. Use private email for security concerns, as described in [SECURITY.md](SECURITY.md).
2. Fork or clone the repository and create a branch for one focused change.
3. Run the static site locally using the instructions in [README.md](README.md).
4. Check the change, then submit a pull request with a short explanation and relevant screenshots.

Publication and final content decisions belong to the repository owner. A pull request does not authorize deployment.

## Project conventions

- Preserve Serene's personal voice, photography, useful content and ownership credit. Do not invent personal facts, qualifications, project results or social profiles.
- Keep HTML, CSS and JavaScript separated. Do not introduce frameworks, dependencies or a build system without an agreed need.
- Keep the existing section structure, working anchors and GitHub Pages asset paths intact.
- Make visual changes work in light and dark mode, across phone, tablet and desktop widths.
- Preserve keyboard access, visible focus, accessible labels and reduced-motion behaviour.
- Do not include personal credentials, editor files, local caches or unrelated changes.

## Validation

Run `node --check script.js` if Node.js is available and `git diff --check`. There is no configured build command or automated test suite.

Check the changed behaviour in a browser, including navigation, the mobile menu, theme preference after reload, image loading, CTA links and the console. For layout changes, include screenshots of both themes and at least a phone and desktop view. State clearly which checks you performed and any limits.

## Licensing and conduct

Code contributions must be compatible with the repository's [MIT License](LICENSE). Personal assets and biographical content have separate reuse restrictions documented in the README. Follow the [Code of Conduct](CODE_OF_CONDUCT.md).
